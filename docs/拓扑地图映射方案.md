> ## ⛔ 状态：**已废弃，不予实施**（2026-09-20 决定）
>
> **原因**：方案虽技术可行，且已按 §3 口径**完整开发并部署验证通过**（天地图在线底图 + 设备拖拽定位），

> 同内容已沉淀进 skill `aiops-platform-domain` → `references/geo-map.md`。
>
> 下文 §3 及之后描述的**接口、文件、迁移、UI 均为当时的实施记录，当前代码库中已不存在**，勿按此施工。

> 版本：v1（2026-09-20）
> 结论：**技术可行**；主要工作量不在"画地图"，而在**补一套空间数据底座**（站点表 + 坐标录入）。

## 1. 需求与已确认口径

在「拓扑发现」模块新增**地图映射视图**，把设备按其所在地理位置落到地图上。

| 决策点 | 结论 |
|---|---|
| 部署环境 | **未定，两种都会有** → 底图必须做成**在线 / 离线可切换** |
| 地图形态 | **真地理地图**（省 / 市 / 区县尺度）→ 无法用自绘示意图绕开合规 |
| 定位粒度 | **站点级**：1 个点 = 1 个机房/局点，点开列出该站点设备 |

> **实施口径调整（2026-09-20，华哥确认）**：本版**先做在线天地图 + 设备级拖拽定位**，不做离线。
> 即：不做 `sites` 站点表，改为在 `devices` 上直接加经纬度，一个设备一个点，人工拖到地图上定位。
> 落地形态是「拓扑发现」下新增子模块 **地图拓扑**（独立路由 `/topology/map`），**现有力导向拓扑页完全不动**。
> 站点表属"待需要时再补"的演进方向（见 §13）。

## 2. 合规前提（硬约束，不可协商）

### 2.1 允许的地图源

只允许 **腾讯地图、高德、百度、天地图（国家地理信息公共服务平台）**。
**Google / Apple / Bing 海外版 / Mapbox / OpenStreetMap 一律不可用。**

### 2.2 「离线地图」的第二层约束

地图瓦片属于**测绘成果**，受《测绘法》《地图管理条例》约束：

- ❌ **自行下载、抓取瓦片制作离线包不合规**（未取得测绘资质不得采集/加工地理信息数据）；
- ✅ 合规离线瓦片只能从**有资质单位**取得：天地图省级节点、各地测绘院、有资质的图商离线授权；
- ⚠️ 腾讯、高德**基本不对外授权离线**；**天地图是唯一有正规离线渠道的主流来源**。

### 2.3 一个需要澄清的误解

**合规红线约束的是「地图数据来源」，不是「渲染库」。**
Leaflet / OpenLayers 等开源渲染库本身不设限 —— 只要瓦片来自合规来源即可。

### 2.4 输出物中的密钥处理

本方案交付代码**不内嵌任何地图 API Key**，统一使用占位符：

```js
key: "请到天地图开放平台申请自己的 KEY 后替换此占位符"
```

客户现场需自行申请（天地图个人/单位 key 免费，配额足够本项目使用）。

## 4. 总体架构：一套渲染 + 双模底图

### 4.1 核心决策：渲染统一用 Leaflet，底图用天地图

| 方案 | 在线 | 离线 | 渲染代码 |
|---|---|---|---|
| 腾讯 GL JS | ✅ 视觉好 | ❌ 封闭 SDK，**无法加载离线瓦片** | 两套 |
| **Leaflet + 天地图** | ✅ WMTS 在线服务 | ✅ 同一套瓦片 | **一套** |

**选定：Leaflet + 天地图。** 理由：

1. 天地图是**唯一同时具备在线服务与正规离线渠道**的合规来源；
2. 在线走官方 WMTS 接口，离线时仅替换 tile URL 模板，**前端渲染代码零改动**；
3. 天地图使用 **CGCS2000 坐标系（≈WGS-84）**，Leaflet 原生支持，**免坐标转换**（见 §7）；
4. 政务类客户对天地图接受度最高，测评时更好解释。

> 代价：天地图视觉风格偏政务、POI 较弱。若客户强烈要求腾讯/高德的视觉效果，可作为"仅在线模式"的附加底图，但需额外处理 GCJ-02 转换，且离线时无法降级 —— **默认不做**。

### 4.2 底图切换

Leaflet 自带 `L.control.layers` 多底图切换控件，天然满足"在线/离线两种都有"：

```
底图图层组
├── 天地图·矢量（在线 WMTS）
├── 天地图·影像（在线 WMTS）
└── 本地离线瓦片（XYZ 目录，离线时启用）
```

启动时探测离线瓦片目录是否存在 → 决定默认底图与是否显示切换控件。

### 4.3 数据流

```
devices 表 ──┐
             ├─→ GET /api/v1/topology/map ─→ TopologyMap.vue
sites 表 ────┘        （按站点聚合）           └─→ Leaflet 打点 + 弹层
topology_links ─────────────────────────────────→ 站点间连线（聚合）
```

## 5. 数据模型设计

### 5.1 新增 `sites` 表

```python
class Site(Base):
    __tablename__ = "sites"

    id          = Column(Integer, primary_key=True)
    name        = Column(String(128), nullable=False, unique=True)   # 局点/机房名
    address     = Column(String(256))                                # 详细地址
    province    = Column(String(32))                                 # 省
    city        = Column(String(32))                                 # 市
    district    = Column(String(32))                                 # 区县
    longitude   = Column(Numeric(10, 7), nullable=False)             # 经度
    latitude    = Column(Numeric(10, 7), nullable=False)             # 纬度
    contact     = Column(String(64))                                 # 现场联系人
    phone       = Column(String(32))
    remark      = Column(String(512))
    created_at  = Column(DateTime, default=datetime.utcnow)
    updated_at  = Column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)
```

**坐标系约定：库里统一存 WGS-84**（≈ 天地图 CGCS2000，差异在厘米级可忽略），前端渲染零转换。

### 5.2 `devices` 表扩展

```python
site_id = Column(Integer, ForeignKey("sites.id", ondelete="SET NULL"), nullable=True, index=True)
```

⚠️ **必须写迁移**：`create_all` 不会修改已存在的表结构（本项目已踩过这个坑）。
`device.py` 现有 `location` 字段**保留不动**（历史数据与导出列仍在用），站点作为结构化补充。

### 5.3 迁移与兼容

- 新增 `sites` 表由 `create_all` 自动建；
- `devices.site_id` 需显式迁移；
- **存量设备 `site_id` 为 NULL** → 地图视图提供"未定位设备"计数与列表入口，引导补录，不静默丢弃。

## 6. 后端接口设计

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/v1/sites` | 站点列表（支持按省市筛选、关键字搜索） |
| `POST` | `/api/v1/sites` | 新建站点 |
| `PATCH` | `/api/v1/sites/{id}` | 修改站点 |
| `DELETE` | `/api/v1/sites/{id}` | 删除站点（设备 `site_id` 置 NULL，**不删设备**） |
| `GET` | `/api/v1/topology/map` | **地图视图专用聚合接口** |

`GET /topology/map` 返回结构：

```json
{
  "code": 0,
  "data": {
    "sites": [{
      "id": 1, "name": "总部机房", "address": "…",
      "longitude": 120.15, "latitude": 30.28,
      "device_count": 42,
      "status": { "online": 40, "warning": 1, "offline": 1 },
      "has_alert": true
    }],
    "links": [{ "source_site_id": 1, "target_site_id": 2, "count": 3 }],
    "unlocated": { "count": 5, "devices": [{"id": 9, "name": "…"}] }
  }
}
```

设计要点：

- **站点聚合在后端做**，前端不重算（本项目已有教训：前端自算口径会与后端对不上）；
- `status` 用状态计数，供地图标记按状态配色；
- `unlocated` 显式返回，避免"设备凭空消失"；
- 站点间链路按 `source_site → target_site` 聚合去重（多条设备间链路折叠成一条站点间线，带 count）。

## 7. 坐标系（必读，最容易出事故的地方）

| 来源 | 坐标系 | 偏移量级 |
|---|---|---|
| 天地图 | CGCS2000（≈WGS-84） | 基准 |
| 腾讯 / 高德 | GCJ-02（火星坐标） | 相对 WGS-84 偏移 **50–500 m** |
| 百度 | BD-09 | 在 GCJ-02 上再偏移 |

**若混用不同来源的底图而不做转换，同一个机房会漂移几百米** —— 表现为"设备点落在隔壁小区"，且很难排查。

**本方案的做法**：数据库统一存 WGS-84，底图统一用天地图 → **全链路无转换**。
将来若引入腾讯/高德底图，必须在前端加 WGS-84 → GCJ-02 转换层（公开算法，纯前端可实现）。

## 8. 离线瓦片方案

### 8.1 获取渠道（**采购事项，非开发事项**）

| 渠道 | 说明 |
|---|---|
| **天地图省级节点** | 首选。各省地理信息公共服务平台，可申请内网部署包 |
| 当地测绘院 / 地理信息中心 | 政府类项目常走这条 |
| 有资质的图商 | 需确认其测绘资质与授权范围 |

### 8.2 格式与托管

- **格式**：XYZ 目录结构 `tiles/{z}/{x}/{y}.png`（Leaflet 直接可用），或打包成 MBTiles；
- **托管**：瓦片目录放在**前端静态目录旁**（生产环境前端本就是外置的 `AIOps-Windows/frontend/dist`），由现有静态服务直接提供，**无需改后端**；
- 建议瓦片目录**独立于 `dist`**，避免每次前端发版把几十 GB 瓦片一起打包。

### 8.3 体积估算（用于采购谈量与磁盘规划）

| 范围 | 层级 | 大致体积 |
|---|---|---|
| 单省 | 1–12 级 | 1–3 GB |
| 单省 | 1–16 级（含街道） | 8–20 GB |
| 全国 | 1–10 级 | 8–15 GB |

**建议**：本项目场景是"看设备分布 + 站点定位"，**单省 1–12 级足够**，无需到街道级。

## 9. 前端设计

### 9.1 页面改动

- `views/Topology.vue`：新增**视图模式切换**（「拓扑图」/「地图视图」），现有力导向图逻辑不动；
- 新增 `views/TopologyMap.vue`（或 `components/TopologyMap.vue`）承载地图；
- 新增 `views/Sites.vue` **站点管理页**（CRUD + 坐标拾取），挂在设置下；
- `views/Devices.vue` 设备表单增加「所属站点」下拉（现有「位置」文本保留）。

### 9.2 地图交互

- 站点标记按状态配色，**告警站点加视觉强调**；
- 点击站点 → 详情弹层：站点名 / 地址 / 设备列表（可跳设备详情）；
- 缩放到省/市级时，相邻站点会重叠 → 引入 `Leaflet.markercluster` 聚合；
- 站点间链路用 `L.polyline` 弧线绘制，标注链路条数。

### 9.3 弹层实现必须遵守本项目既有规范

⚠️ 项目历史坑：弹层会被带 `animate-in` 的祖先 `transform` 劫持成包含块，导致"要滚回顶部才看得见"。

- 新弹窗一律 `<Teleport to="body">`；
- 外层 `fixed inset-0 flex overflow-y-auto bg-black/60 p-4`，内层 `m-auto`；
- **不要用 `items-center`**（内容超高时会把顶部推出可视区）。

### 9.4 坐标录入体验（决定台账质量的环节）

站点新建/编辑页提供**地图拾取**：内嵌一张地图，点一下即回填经纬度；同时支持手填、支持从地址地理编码（需天地图 key 的 Geocoder 接口）。

**这一步的易用性直接决定客户愿不愿意维护台账** —— 见 §11 风险 1。

## 10. 实施计划

| 阶段 | 内容 | 前置 | 粗估 |
|---|---|---|---|
| **1 · 数据底座** | `sites` 表 + `devices.site_id` + 迁移；`/sites` CRUD；站点管理页；设备表单加站点选择 | 无 | 2–3 人天 |

## 11. 风险与依赖

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| 1 | **台账没人维护** | 功能交付即废（网管类项目常见死法） | 站点级定位把工作量从"每台设备"降到"每个机房"；提供地图拾取降低录入成本；地图视图显式提示"未定位设备 N 台" |
| 2 | **离线瓦片采购周期不可控** | 阻塞阶段 3 | 尽早启动采购询价；阶段 1/2 先用在线底图推进，不等瓦片 |
| 3 | **坐标系混淆导致点位漂移** | 点位错几百米，且难排查 | §7：库统一存 WGS-84、底图统一天地图，全链路零转换 |
| 4 | 省/市级缩放下站点重叠 | 地图不可读 | `markercluster` 聚合 |
| 5 | 政府客户对坐标敏感 | 可能要求脱敏或不显示精确坐标 | 预留"坐标精度降级"开关（如只显示到市级） |
| 6 | 地图合规解释 | 测评/验收被追问 | 全程使用天地图，来源可追溯、可出示授权；代码不内嵌任何 key |

## 12. 待确认事项

1. **瓦片采购**：客户是否有预算与渠道？天地图省级节点的申请主体是客户还是我方？
2. **覆盖范围**：只覆盖客户所在省/市，还是全国？（直接决定瓦片体积与费用）
3. **坐标录入责任方**：由客户提供机房台账导入，还是现场逐点标定？
4. **是否要"设备级"精度**：当前按站点级设计，数据模型可平滑扩展（未来给 `devices` 加 `latitude/longitude` 即可）。
5. **地图是否对外可见**：若平台有对外门户，地图展示范围需再评估（当前位置数据属敏感信息）。

| `GET` | `/api/v1/topology/map` | 已定位设备 + **未定位清单** + `summary`（计数由后端算） |
| `PATCH` | `/api/v1/topology/map/position` | 单台坐标；两个坐标传 null = 取消定位 |
| `POST` | `/api/v1/topology/map/positions` | 批量坐标（先全量校验再写，避免"存一半"） |
| `DELETE` | `/api/v1/topology/map/position/{id}` | 清除定位（只清坐标，不删设备；DELETE 需 admin） |

**已知取舍**：
- 缩放控件放右下（左上被统计浮层占用、右上被详情卡占用）；
- 浮层 z-index 必须 > 1000 —— Leaflet 控件的 z-index 是 800/1000，且地图容器不创建层叠上下文，用 500 会被控件盖住；
- 详情卡用 `absolute` 浮卡而非 `fixed` 模态，规避项目既有的"祖先 transform 劫持 fixed 定位"的坑；
- `divIcon` 拼接设备名必须 `esc()`（存储型 XSS）。
